## The project in five sentences

Prisma is replacing a service's "custom domain" with a new platform object, the RoutingUrl: a hostname connected to a service, which can be saved before its DNS exists and becomes active by itself once its ownership TXT record and its CNAME resolve. A workspace proves it owns a domain through a second object, the domain ownership. Composer's `publicUrl()` lets an author declare which service is public and at which hostname; today a named hostname lowers to Alchemy's `Prisma.CustomDomain`. This project gets a `Prisma.RoutingUrl` resource into Alchemy, then switches Composer to it, then makes the platform's `prisma.build` address a RoutingUrl too. The platform side (pdp-control-plane) is run by another session, vetinari-29, session id `local_49d337ad-4041-4ce3-ab15-fc9e739fe696`.

## How the two resources decide a row is theirs (the result of 2026-11-23)

Both `Prisma.DomainOwnership` (`packages/prisma/src/internal/DomainOwnershipProof.ts`) and `Prisma.CustomDomain` (`packages/prisma/src/CustomDomain.ts`) look for an existing row twice: at the start of `reconcile`, and again directly before the create (in `Prisma.CustomDomain`, before every create attempt). A row found and not recorded goes through the adoption rule: `Prisma.DomainOwnership` takes an `unverified` row and otherwise needs `--adopt`; `Prisma.CustomDomain` fails with "already exists". A create that succeeds returns a row the resource owns. The domain ownership create is resent by Alchemy's deploy retry policy (`packages/prisma/src/Providers.ts`); the custom domain create is resent only when throttled (`resendOnlyThrottled`).

What is knowingly not detected: a row another actor creates between the last look and the end of the create. Two stacks that hit that window record the same row, and destroying either removes it for both.

The full reasoning, the two plan reviews and the two code review rounds are in `slices/u2-routing-url-resource/remove-http-status-plan.md` and `slices/u2-routing-url-resource/reviews/remove-http-status/`. Both reviewers judged the pushed tips ready. One reviewer suggestion was not taken: renaming `foundAfterDnsWait` in `CustomDomain.ts` (code review round 2, F09); the other reviewer accepted the name.

## Facts about the platform, checked against its `main` on 2026-11-23

Will: "what is on main is in production." Read the control plane from GitHub (`gh api "repos/prisma/pdp-control-plane/contents/<path>?ref=main" -H "Accept: application/vnd.github.raw"`), never from a local checkout: two reviews in this session reasoned from a checkout of 2026-11-18 that the platform had replaced, and it cost a round of corrections.

- `POST /v1/workspaces/{id}/domain-ownerships` looks the TXT record up at once and returns the row `verified` when the record carries the workspace's value, `unverified` otherwise. It is idempotent: `201` then `200` with the same row (checked live).
- `POST /v1/services/{id}/domains` (`createCustomDomain` in `packages/interactors/src/compute/domains.ts`) makes a RoutingUrl row, syncs it inside the request, and when the row ends up holding no custom domain it soft-deletes the row and answers the refusal (`400` DNS not configured, `422` `domain-ownership-required`, `503`, `429`, `409`). If a Foundry call fails it throws (`500`) and keeps the row, whose queued retry may register the custom domain later.
- `GET /v1/services/{id}/domains` lists only live RoutingUrl rows that hold a custom domain. So `Prisma.CustomDomain`'s look before each attempt cannot find its own half-made row.
- A check of a RoutingUrl can retry a failed certificate, which takes one of the workspace's 10 certificate orders per hour.
