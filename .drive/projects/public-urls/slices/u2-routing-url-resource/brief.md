# Brief: finish and hand over the Alchemy and Distilled pull requests for Prisma hostnames

## Why this work exists

Composer's `publicUrl({ id, url, target })` gives a service a hostname in each environment. Today a Composer deploy fails until the user has published the domain's ownership TXT record and the CNAME. Prisma's API now lets a hostname be created before its DNS exists; it starts serving on its own once the records appear. Composer reaches that API through Alchemy, and Alchemy's Prisma client is generated by Distilled. So Alchemy and Distilled need support for it before Composer can use it.

That support is already built and reviewed. Your job is to finish it once Prisma ships the last piece of its API, and get it ready for Will to open as two upstream pull requests.

The REST protocol reads the HTTP status, so Alchemy can tell "created" from "already existed". ## What blocks it

Prisma must ship distinct error codes for the hostname create and update refusals. Today Alchemy tells these refusals apart by matching error message text, which is fragile. The proposed codes are `logical-id-taken`, `invalid-hostname` and `service-on-another-branch`. They ship with Prisma's work to make the `*.prisma.build` address a hostname record like any other (slice 8 in the platform plan). On 18 November it was not scheduled.

Will also decided that the two upstream pull requests open only after Prisma's whole hostname API has shipped, so the Alchemy team reviews one pull request per repository.
