# Deferred

- **Preflight does not see a value a user set on one service.** A platform variable set only as a service variable, through Console's "Save and Deploy", is reported unset, and a required one fails the deploy. The fix is one `resolved-variables?serviceId=` read per reading service that already exists, with each key's `updatedAt` added to that service's triggers. Not built because Composer has no way to declare such a value. From the design, section 4.1.
- **Hints use `prisma project env` for the built-in groups.** Move them to `prisma variable` when it is the CLI most users have.
- **An app upgrading directly from a version before the address change** can have one service receive another's old row once. The guide tells it to deploy with a release from 0.35.0 to 0.39.0 first. A check in preflight against the deploy state would refuse it instead.
- **A local client type and a cast stand in for the SDK's description of the resolved-variables read.** `ResolvedVariablesClient` and its `blindCast` in `packages/1-prisma-cloud/1-extensions/target/src/preflight.ts` exist because `@prisma/management-api-sdk` does not describe `GET /v1/projects/{projectId}/resolved-variables`. Remove both and use the SDK's types when it does.
- **The custom-group hint is a sentence because `prisma variable add … --group` does not exist.** When the CLI ships it, replace the sentence in `setCommands` with the command, and change ADR-0064's sentence that says no released CLI command writes to a custom group.
- **`scripts/e2e-first-deploy.ts` writes branch overrides and production rows with no group.** For a non-production environment it posts `class: preview` with a `branchId`, which the platform will reject; for production it posts a row with no `groupId`, which the resolved-variables read does not list. Slice 3 must change it to write to the branch's group.
- **`branchId ?? defaultBranchId` is still computed outside the container**, in `attachmentBranchIdOf` (`descriptors/shared.ts`, on `CloudApplication`) and in lowering's `deployed.ts`, on their own types. Minor; `PrismaCloudContainer.deployBranchId` is the one definition in the container.
- **Ask the platform to put the limit and the count in its quota error for service variables.** Composer checks its own count, but cannot count variables a user set in Console.
